# 01. 워크숍 개요

> 현재 공통 실습: 샘플은 사본 없이 저장소의 `sample_downloads/`에서 직접 사용합니다. **폴더 고르기 → 샘플 폴더 → 이 폴더 사용**으로 선택하며, 이동 결과·노트·갤러리도 같은 폴더에서 확인합니다. 아래 초기 설계의 사본 절차는 개인 폴더 사용에만 해당합니다. 현재 실행 안내는 [GUIDE 0-6](../GUIDE.md#0-6-화면과-실습-폴더)을 따릅니다.

> 처음 보는 말(에이전트, 루프, 도구, MCP, 스킬, API, 하네스 등)은 [용어 풀이](00_glossary.md)에 쉬운 예시와 함께 있습니다.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 이름 | 에이전트 만들기 워크숍 (가제) |
| 길이 | 4시간 = 1~2시간차(함께 겪기) + 3~4시간차(내 에이전트) |
| 대상 | 디자인 전공 3·4학년 약 16명 |
| 학생이 이미 아는 것 | Cursor, Claude 사용. 본인 API 키 보유 |
| 학생이 모르는 것 | 에이전트 개념(루프, 도구, MCP 등). 파이썬은 몰라도 됨 |
| 진행 | 강사 1명, 프로젝터 1대, 학생 노트북(Mac/Windows 섞임) |
| 공통 에이전트 | 「내 파일 큐레이터」 = 「내 다운로드 폴더 전시회」 |
| 결과물 | 내 전시회 갤러리 HTML, 실제로 정리된 사본 폴더, 내 에이전트 스토리보드와 다이어그램 |

## 2. 목표

**학습 목표는 파이썬이 아니라 "에이전트가 어떻게 움직이고, 무엇이 가능한가"를 이해하는 것입니다.**

| # | 학생이 이해하고 느끼는 것 | 끝났을 때 학생이 하는 말 |
|---|---|---|
| G1 | AI는 말만 하는 뇌다. 손(도구)을 줘야 세상을 만진다. LLM은 고르기만 하고, 실행은 코드가 한다. | "아까 그 AI는 몰라서가 아니라 손이 없어서 틀린 거구나." |
| G2 | 에이전트는 고르고 → 해 보고 → 결과를 보고 → 다시 고르는 루프다. 언제 멈출지도 설계한다. | "결과를 보고 다음 걸 스스로 정하더라." |
| G3 | 에이전트 만들기의 대부분은 디자인이다. 손을 꽂고(MCP), 일하는 법을 적고(스킬), 길을 정하고(그래프), 사람이 끼어들 자리를 정한다(승인). | "내가 한국어로 쓴 규칙대로 움직였어. 그게 내 디자인이야." |
| G4 | (느낌) 내 진짜 파일로 진짜 결과가 나왔다. 내 아이디어에도 쓸 수 있겠다. | "오, 이게 진짜 되네? 내 에이전트는 이렇게 생겼어." |

> 예전 초안(v0.4)은 이 목표를 L1~L4라고 불렀습니다. 지금은 **L1~L4를 자율성 단계 이름으로 씁니다**(아래 4장). 헷갈리지 않도록 학습 목표는 G1~G4로 바꿨습니다.

학생이 만나는 개념:

| 개념 | 한 줄 설명 | 나오는 장면 |
|---|---|---|
| 루프 | 고르고 → 실행하고 → 결과를 보고 → 다시 고름 | 장면 2 |
| 도구 | LLM이 고를 수 있는 "손". 실행은 코드가 함 | 장면 0→2 |
| MCP | 남이 만든 손을 표준 콘센트로 꽂음 | 장면 3 |
| 웹 검색·읽기 | 에이전트가 인터넷을 찾고 읽음 | 장면 3, 6 |
| 스킬 | 필요할 때만 꺼내 읽는 업무 매뉴얼(`SKILL.md`) | 장면 4 |
| 사람 승인 | 계획을 보여 주고 사인을 받은 뒤에만 실행 | 장면 5 |
| 그래프 | 정해진 길(노드와 화살표) 위에서 일함 | 장면 5 |
| 외부 API | 진짜 서비스(메트로폴리탄 미술관)에서 진짜 데이터 | 장면 6 |
| 멀티에이전트 | 역할이 다른 에이전트 둘이 나눠 일함 | 장면 6 |

## 3. 4시간 구조

| 시간 | 이름 | 학생이 하는 것 | 결과물 |
|---|---|---|---|
| 1~2시간차 | **함께 겪기** | 같은 에이전트를 단계별로 켜 보며 개념을 하나씩 만남. 따라 치는 코딩이 아님 | 내 전시회 갤러리, 정리된 사본 폴더, 내 `SKILL.md` |
| (마지막 17분) | 내 에이전트로 옮기기 | 「내 에이전트 스토리보드」 작성 → Claude가 원리 표와 다이어그램 추출 → 빨간 펜으로 고침 | 스토리보드, 원리 표, 다이어그램 |
| 3~4시간차 | **내 에이전트** | 세 트랙 중 하나를 골라 만듦 | 시연 1개 |

3~4시간차 트랙:

| 트랙 | 이름 | 이런 기획에 | 완료 기준 |
|---|---|---|---|
| A | 부품 바꾸기 | 글·사진 + LLM + 로컬 파일만으로 핵심 동작이 되는 기획 | 한 실행에서 도구 2회 이상 연쇄 + 저장 + 결과 화면 |
| B | 다이어그램 + 부분 시제품 | 공식 API가 없거나, 하드웨어·실시간·다중 사용자가 필요한 기획 | 다이어그램 1장 + 한 조각이 실제로 도는 기록 1개 |
| C | 오즈의 마법사 | 기능보다 경험·감정이 핵심인 기획 | 짝과 리허설 1회 + 관찰 기록 3개 + 부품 매핑 1장 |

3~4시간차 진행(초안):

| 순서 | 블록 | 분 | 내용 |
|---|---|---|---|
| 1 | 트랙 고르기 | 12 | 스토리보드 원리 표를 보고 트랙 선택 |
| 2 | 제작 1 | 53 | A: 내 페르소나와 스킬로 1회 실행 / B: 다이어그램 완성과 범위 확정 / C: 시나리오와 마법사 대본 |
| 3 | 휴식 | 8 | |
| 4 | 제작 2 | 25 | A: 도구·결과 화면 교체 / B: 한 조각 동작 / C: 짝과 리허설 |
| 5 | 시연 준비 | 7 | 리플레이 파일이나 시연 대본 확정 |
| 6 | 시연 | 15 | 1인 약 50초 |
| | **합계** | **120** | |

규칙: 트랙 변경은 휴식 전까지 1회. 막히면 A → B → C로 내려가도 됩니다.

## 4. 가르치는 방법 (Andrew Ng "Agentic AI" 코스에서 가져옴)

| 방법 | 수업에서 어떻게 |
|---|---|
| "사람이라면 어떻게 할까?" | 개념마다 "사람 인턴이라면"으로 시작합니다 |
| 실패 먼저, 도구 하나로 뒤집기 | 도구 없는 AI가 틀리는 장면을 먼저 보여 주고, 도구 하나를 켜서 뒤집습니다 |
| 자율성을 한 단계씩 | L1 → L4로 올립니다(아래 표) |
| 거의 완성된 코드 | 학생은 버튼, 설정 한 줄, 한국어 파일, Cursor에게 하는 부탁 한 문장만 바꿉니다 |
| 학생 손이 먼저 | 강사 시연은 장면마다 3분 이내. 나머지는 학생이 직접 합니다 |

자율성 단계:

| 단계 | 이름 | 누가 순서를 정하나 | 수업 장면 |
|---|---|---|---|
| L1 | 챗봇 | 없음(말만 함) | 장면 0 |
| L2 | 고정 워크플로 | 코드 | 장면 1 |
| L3 | 도구를 고르는 에이전트 + 사람 승인 | LLM이 고르고, 쓰기는 사람이 승인 | 장면 2~5 |
| L4 | 에이전트 여럿 | LLM 둘 + 코드가 넘겨줌 | 장면 6 |

## 5. 이 수업이 아닌 것

| 아닌 것 | 이유 |
|---|---|
| 코딩 에이전트 만들기 | 대상이 디자이너입니다. 자유도는 페르소나, 스킬, 대상 폴더, 연결 서비스, 자율성 단계를 바꾸는 데서 나옵니다 |
| 파이썬 수업 | 코드는 거의 완성본으로 줍니다 |
| 따라 치기 실습 | 체험과 관찰이 중심입니다 |
