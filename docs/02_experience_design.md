# 02. 경험 설계: 「내 다운로드 폴더 전시회」 (1~2시간차)

> 처음 보는 말(에이전트, 루프, 도구, MCP, 스킬, API, 하네스 등)은 [용어 풀이](00_glossary.md)에 쉬운 예시와 함께 있습니다.

> 기준 문서: `docs/archive/experience_design_v0.4.md` 1~7장 + 이후 대화에서 정한 결정. 둘이 다르면 **이 문서가 우선**합니다.
> 바뀐 주요 결정: 웹 읽기는 Fetch MCP 대신 **Tavily MCP**(`tavily_search`, `tavily_extract`). 수업은 **스타터 웹앱 하나**(왼쪽 채팅, 오른쪽 Loop Theater)로 진행. 인간 루프 연극은 삭제.

## 1. 이야기 한 줄

> 엉망인 내 다운로드 폴더(의 사본)를, 탐정이 뒤져서 내가 어떤 사람인지 추리하고, 큐레이터가 내 규칙대로 전시실을 나눠 **내 승인을 받아 진짜로 옮기고**, 도슨트가 메트로폴리탄 미술관에서 닮은 명작을 찾아 해설을 붙여 **전시회 웹페이지**를 엽니다.

| 역할 | 하는 일 | 쓰는 손(도구) | 자율성 |
|---|---|---|---|
| 🕵️ 탐정 | 사본 폴더를 뒤져 "폴더 주인은 어떤 사람인가"를 추리 | 파일 읽기 도구, 웹 검색(Tavily) | L3 |
| 🗂️ 큐레이터 | 학생이 쓴 `SKILL.md` 규칙대로 전시실과 새 이름을 계획. 항목마다 승인받고 진짜로 옮김 | `SKILL.md`, 계획 도구, 이동 도구(삭제 없음) | L3 |
| 🎧 도슨트 | 전시실마다 Met 미술관에서 닮은 작품 1점을 골라 걸고, 위키백과를 읽어 해설을 씀 | Met API 도구, `tavily_extract` | L4 |

## 2. 수업 화면: 스타터 웹앱 하나

```
┌─ 상단: [L1 챗봇] [L2 워크플로] [L3 에이전트] [L4 에이전트 둘]   도구: [파일] [웹 검색] [MCP] [Met API] ─┐
│ 왼쪽: 채팅                         │ 오른쪽: Loop Theater (실시간 시각화)                          │
│  - 학생이 말을 겁니다              │  - 턴 카드: 🧠 LLM 판단 → 🔧 도구 호출 → 결과                 │
│  - 승인 카드가 여기에 뜹니다       │  - 지금 일하는 부품(뇌/손/스킬/승인)과 에이전트 노드에 불     │
│    ✅ 승인 ❌ 거절 ✏️ 수정 💬 한마디 │  - 재시도 대기(429/503)도 카드로 보임                         │
│                                    │  - 리플레이, 프로젝터 모드(큰 글씨)                           │
└────────────────────────────────────┴────────────────────────────────────────────────────────────────┘
```

수업 흐름:

| 단계 | 학생이 하는 것 | 알게 되는 것 |
|---|---|---|
| 1 | 상단 버튼을 켜고 끕니다 | 단계와 도구에 따라 행동이 바뀜 |
| 2 | 버튼이 사실은 파일 한 줄이라는 것을 봅니다 | `config.yaml`, `persona.md`, `SKILL.md`, `mcp.json` |
| 3 | 그 파일을 직접 고치거나 Cursor에게 부탁합니다 | 내가 디자인한 대로 움직임 → 3~4시간차의 출발점 |

노드 그래프(에이전트·단계 그림)는 **보기 전용**입니다. 그래프를 편집하는 기능은 만들지 않습니다.

미션 카드: 단계(L1~L4)마다 미션 카드 1장이 있고, 막히면 `levels/Lx_done/` 완성본으로 바꿔 실행할 수 있습니다.

## 6. 「내 에이전트 스토리보드」 템플릿 (H9)

흐름: **① 말로 쓰기(6분) → ② 6컷 그리기(5분) → ③ Claude로 원리 뽑기(3분) → ④ 빨간 펜으로 고치기(3분)**

### 6.1 ① 말로 쓰기 (10문항)

> 사람 인턴에게 일을 맡긴다고 생각하고 쓰세요. 기술 용어는 몰라도 됩니다.

| # | 질문 | 내 답 (2~3문장) |
|---|---|---|
| 1 | 내 에이전트의 이름과 캐릭터는? 누구처럼 말하나? | |
| 2 | 언제 일을 시작하나? (말을 걸 때 / 사진을 찍을 때 / 매일 밤 10시 …) | |
| 3 | 무엇을 받나? (말, 글, 사진, 소리, 파일, 날씨, 위치 …) | |
| 4 | 사람 인턴이라면 어떤 순서로 일할까? 다섯 문장으로 | |
| 5 | 무엇을 기억해야 하나? | |
| 6 | 어디서 고민하나? ("만약 ~라면 ~하고, 아니면 ~한다") | |
| 7 | 무엇을 만들어 주나? (카드, 포스터, 목록, 알림 …) | |
| 8 | 어디서 나에게 꼭 물어봐야 하나? | |
| 9 | 절대 하면 안 되는 것은? (남의 개인정보, 결제, 위치 공유 …) | |
| 10 | 바깥 세상의 무엇이 필요한가? 오늘 본 것 중 비슷한 손은? | |

|---|---|---|---|---|
| 1 시작 | | | | |
| 2 | | | | |

### 6.3 ③ Claude로 원리 뽑기 (복사해서 쓰는 프롬프트)

```
너는 에이전트 설계 도우미야. 아래는 디자인 전공 학생이 쓴 "내 에이전트" 설명과 스토리보드야.
코드는 쓰지 말고, 학생 말을 존중해서 아래 형식으로만 정리해 줘. 학생이 안 쓴 것은 지어내지 말고 "(미정)"이라고 써.

1. 원리 표 (각 칸 1~2줄)
| 요소 | 내용 | 학생 문장 근거(인용) |
| 트리거(언제 시작) | | |
| 입력 | | |
| 도구(필요한 손) | | |
| 기억 | | |
| 결정(갈림길, 조건) | | |
| 출력 | | |
| 사람 승인 지점 | | |
| 금지 사항 | | |
| 바깥 서비스/API/MCP 후보 | | |

2. 자율성 단계 L1~L4 중 어디인지와 이유 1줄
   (L1 챗봇 / L2 고정 워크플로 / L3 도구를 고르는 에이전트 + 사람 승인 / L4 에이전트 여럿)
3. 루프형인지 그래프형인지와 이유 1줄
4. mermaid flowchart 1개 (노드 10개 이하, 한국어 라벨, 승인 지점은 마름모로)
5. 오늘 워크숍 부품 매핑: 도구 / MCP / 스킬 / 기억 / 승인 / 렌더 중 무엇을 쓰면 되는지
6. 설명이 모호해서 학생에게 되물어야 할 질문 3개
```

### 6.4 ④ 빨간 펜으로 고치기

1. mermaid를 mermaid.live나 FigJam에 붙여 그림으로 봅니다.
2. **틀린 곳을 빨간 펜으로 고칩니다.** AI의 정리는 초안입니다. 고친 부분이 곧 내 설계 결정입니다.
3. 6번 질문 3개에 답을 적습니다.
4. 사진을 찍어 3~4시간차 첫 장에 붙이고, 이 표로 트랙(A/B/C)을 고릅니다.

| 트리거 | 매일 아침 7시 |
| 입력 | 오늘 일정, 동네 날씨 |
| 도구 | 날씨 API, 일정 읽기, 메시지 보내기 |
| 기억 | 내가 우산을 자주 잃어버리는 요일 |
| 결정 | 비 올 확률이 60%를 넘고 바깥 일정이 있으면 알리고, 아니면 조용히 있음 |
| 출력 | 짧은 아침 메시지 1개 |
| 사람 승인 | 다른 사람에게 메시지를 보낼 때 |
| 금지 | 일정 내용을 밖으로 보내지 않음 |
| 단계 | L3 (도구를 고르고, 남에게 보내기만 승인) |

## 7. 도슨트는 "닮은 명작"을 어떻게 고르나

**결론: 기본은 텍스트(의미) 비교입니다.** "닮음"은 주제와 분위기가 닮았다는 뜻이지 생김새가 닮았다는 뜻이 아닙니다. 학생에게 솔직하게 말합니다. 비전(이미지 비교)은 학생이 동의할 때만 켜는 선택입니다.

| 단계 | 누가 | 무엇을 | 입력 | 출력 | 화면 | 학생 개입(H7) |
|---|---|---|---|---|---|---|
| D1 검색어 만들기 | 도슨트 LLM | 전시실 요약을 보고 **영어 검색어 3개**와 이유 | 전시실 이름, 파일 수, 대표 파일명 5개, 확장자, 큐레이터 캡션. **파일 내용 원문은 보내지 않음** | 예: `["poster", "typography", "sunflowers"]` | 검색어 카드 3장 | 검색어 1개를 고칠 수 있음 |
| D2 후보 찾기 | 코드(도구) | Met API v1.1 검색 → 작품 정보 조회 → **공공 도메인 + 이미지 있는 것만** | 검색어 | 후보 최대 8점(제목, 작가, 연도, 재료, 분류, 태그, 이미지) | 후보 그리드 | — |
| D3 고르기 | 도슨트 LLM | 후보의 제목·재료·태그를 전시실과 비교해 1점 선택 + 이유 1문장 | 전시실 요약 + 후보 정보 | 선택 1점 + 이유 | 고른 작품에 테두리 | 다른 후보로 바꿀 수 있음. 바꾼 기록은 도슨트에게 돌아감 |
| D4 해설 쓰기 | 도슨트 LLM + 웹 | 작품·작가의 위키백과 문서를 읽어 2~3문장 해설 | 작품 제목·작가 | 해설 + 출처 링크 | 웹 읽기 카드 | — |

수업 포인트: D1과 D3은 **LLM의 판단**, D2와 D4는 **도구의 실행**입니다. 장면 2의 "뇌는 고르고 손은 실행한다"가 다시 나옵니다.
