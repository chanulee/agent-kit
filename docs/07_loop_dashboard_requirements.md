## 1. 지금 "루프"라는 개념이 있나?

**코드에는 있지만, 학생에게는 안 보입니다.**

- 메인 코드의 루프는 aisuite `max_turns`가 안에서 돌립니다. 학생이 보는 건 터미널의 `turn 3: 1.2s, tools=[...]` 한 줄뿐입니다.
- 루프를 다루는 손잡이는 흩어져 있습니다: `max_turns`(인자), `WEB_CAP`(환경 변수), `STOP_ON_429`, `EXTRA_RULES`. 학생은 이것들이 "루프를 설계하는 손잡이"라는 걸 알 수 없습니다.

### 1.1 이 수업에서 말하는 "루프 엔지니어링"

> 루프 = 뇌(LLM)가 고르고 → 손(도구)이 하고 → 결과를 보고 → 다시 고르기.
> 루프 엔지니어링 = **그 바퀴를 언제·얼마나·어떤 조건으로 돌리고 멈출지 정하는 디자인.**

학생에게 보여 줄 손잡이 7개(전부 `agent.yaml` 한 파일, 화면에서도 켜고 끔):

| 손잡이 | 기본값 | 바꾸면 보이는 것 | 오늘 시험에서 본 문제 |
|---|---|---|---|
| 턴 한도 `max_turns` | 8 | 3으로 줄이면 추리 도중 멈춤 | — |
| 손(도구) 목록 | 단계별 | 손을 빼면 지어내기 시작 | 손 없는 질문에 "해 봤다"고 거짓말 |
| 웹 호출 한도 `web_limit` | 5 | 한도에 걸리면 "가진 정보로 답해" | 같은 URL 2번 읽기 |
| 같은 호출 반복 막기 | 켬 | 같은 도구·같은 인자는 캐시 결과 + "이미 읽었음" 안내 | 같은 URL 2번 읽기 |
| 승인 지점 `ask_before` | `[move_file]` | 이 도구는 사람 버튼을 기다림 | (Groq) 도구 대신 채팅으로 허락을 물음 |
| 기다렸다 다시 `retry` | 429/503에 최대 4번 | 대기 카운트다운 | 무료 키 429 |
| 기억 `remember_tool_results` | 끔 | 켜면 다음 질문에서 읽은 글을 진짜 기억, 대신 글 양(토큰)이 커짐 | "방금 글" 질문에 지어냄 |

이 7개가 "자유도"의 경계이기도 합니다. 모델은 이 안에서 도구 순서를 **스스로** 고릅니다(에이전트다움). 학생은 경계를 디자인합니다.

### 2.2 오류 카드 형식 (모든 오류가 같은 모양)

```
❌ [단계] 모델 호출 · 턴 2
   무슨 일: 모델 키가 맞지 않습니다 (401)
   할 일:   .env의 ZAI_API_KEY를 다시 붙여 넣고 [다시 시도]
   [다시 시도]  [자세히(원문 오류)]
```

| 단계 | 예 | 학생에게 보이는 말 |
|---|---|---|
| 준비 | 키 없음, 사본 폴더 없음 | "키가 없습니다 → `.env`에 넣고 앱을 다시 켜세요" |
| 모델 호출 | 401, 429, 503, 연결 끊김 | 429/503은 오류가 아니라 **대기 카드**(카운트다운, n/4번째) |
| 도구 | 파일 없음, 사본 밖, Met 결과 없음 | 빨간 줄로 남고 **루프는 계속**. 모델이 다른 방법을 고르는 게 보임 |
| 웹(MCP) | Tavily 키 없음, 한도 초과 | "웹 손이 꺼졌어요(이유) → 나머지 손으로 계속" |
| 승인 | 거절, 수정 | 오류 아님. 노란 카드 → 결과 ✅/❌/✏️ |

### 2.3 사용 · 수정 · 관찰이 한 바퀴 도는 법

1. **사용**: ①에 말을 건다.
2. **관찰**: ②에서 턴이 쌓이는 걸 본다. 이상하면 ④에서 원문을 본다.
3. **수정**: ③에서 손을 끄거나 턴 한도를 바꾼다. 또는 "📄 파일로 보기"로 `persona.md`·`SKILL.md`를 연다(Cursor로 고쳐도 됨).
4. **다시 사용**: 같은 질문을 다시 보낸다. ②에 **이전 실행과 나란히 비교** 버튼(SHOULD).

## 3. 요구사항 (큰 규칙 기준으로 다시 정리)

### ① 키만 넣으면 돈다

| ID | 우선 | 요구사항 | 확인 방법 |
|---|---|---|---|
| R1.1 | MUST | `git clone`(또는 zip) → `.env`에 키 2개 → 명령 하나(`uv run app.py`) 또는 더블클릭(`start.command`/`start.bat`) | 깨끗한 Mac·Windows 각 1대에서 15분 안에 |
| R1.2 | MUST | 기본 모델 하나: GLM(Z.ai). 다른 모델은 `agent.yaml` 한 줄 | `.env.example`과 문서가 같은 모델을 말함 |
| R1.3 | MUST | Node 필요 없음. 웹은 Tavily **원격** MCP. Tavily 키가 없으면 웹 손만 꺼지고 나머지는 동작 | 키 없이 실행 → 상태바에 🌐❌, 앱은 정상 |
| R1.4 | MUST | 고정 경로(`/workspace/...`) 없음. 폴더는 학생이 고름: [샘플] [내 다운로드] [경로 붙여 넣기] → **사본**을 만들어 그 안에서만 작업 | 경로 검색으로 `/workspace` 0건 |
| R1.5 | MUST | 첫 화면 점검표: 키 ✅/❌, 웹 ✅/❌, 사본 ✅/❌, "테스트 한 번 보내기" 버튼 | — |

### ④ 자유도

| ID | 우선 | 요구사항 |
|---|---|---|
| R4.1 | MUST | L3부터 모델이 도구 순서를 스스로 고름(고정 순서는 L2만) |

### 기술 결정

| 결정 | 이유 |
|---|---|
| **aisuite `Agent` + `Runner.run_sync` 그대로 사용**, 우리 코드는 이벤트 받기(TraceSink)·승인(`tool_policy`)·도구 감싸개만 | 루프를 새로 짜지 않음 → 코드가 작고 "aisuite 기반"이 그대로 보임 [확인함] |
| 승인은 `tool_policy`가 화면 버튼을 기다림(차단). ✏️수정은 `move_file`이 계획표 기준으로 처리 | `tool_policy`는 허락/거절만 가능 [확인함] |
| 429/503 재시도는 공급자 호출을 감싸서 기다리고 `retry.waiting` 이벤트를 보냄 | 메인 `common.py` 방식 유지 |
| 화면: 로컬 서버 + 빌드 없는 HTML/JS 한 장 | 설치 없음, 오프라인 리플레이 |

## 4. 16명 수업 롤플레이 (상상)

> 등장: 강사 1, 학생 16(Mac 11, Windows 5 가정). 학생 예시 이름은 지어낸 것입니다.

### 오프닝 (5분)

- **강사**: "다운로드 폴더에 파일 500개 넘는 사람?" — 6명 손.
- **강사**: 화면 첫 칸 점검표를 띄움. "✅ 세 개가 다 초록이면 준비 끝."
- **예상 반응**: 2~3명 ❌. 대부분 `.env` 파일 이름을 `.env.txt`로 저장(Windows 메모장), 또는 키 앞뒤 따옴표·공백.
  - **대비**: 점검표 ❌ 옆에 "이 파일을 여세요" 버튼 + 흔한 실수 3개 안내. 앱이 따옴표·공백은 알아서 제거. `.env.txt`도 읽어 줌.

### 장면 0 · L1 챗봇 (7분)

- 학생: "지금 몇 시야?" → GLM이 그럴듯한 시간을 말함. "내 다운로드에 뭐 있어?" → 일반론.
- **학생 A(빠름)**: "근데 ChatGPT는 시간 알던데요?" → **강사**: "그건 앱이 시계라는 손을 몰래 붙여 준 거예요. 오른쪽 타임라인 보세요. 도구 0번."
- **아하**: 말(①)과 행동(②)이 나란히 있어서 "손이 없구나"가 바로 보입니다.

### 장면 1 · L2 고정 순서 (8분)

- 샘플 폴더로 "요약해 줘" → 항상 같은 3칸. "제일 큰 파일 3개?" → 못 함.
- **학생 B**: "이게 더 안정적인데 왜 에이전트를 써요?" — 좋은 질문. **강사**: "맞아요. 다음 장면에서 자유를 주면 뭐가 좋아지고 뭐가 위험해지는지 같이 봐요." (자유도와 통제의 균형이 수업의 큰 줄기)

### 장면 2 · L3 탐정 + 루프 손잡이 (15분)

- [사본 만들기]: **학생 C**: "제 다운로드 진짜 보여 주기 싫어요." → 샘플 폴더(부끄러운 일 아님). 실제로 3~4명은 샘플을 쓸 것.
- 탐정 실행 → 턴 카드 5~8장. "단서 때문에 다음 파일을 고르는 것"이 보임.
- `max_turns` 3 → 추리 도중 멈춤. **반응**: 웃음. "얘 성격 급하네."
- **예상 문제**: 동시에 16명이 부르면 GLM 429 → 상태바 "⏳ 12초 대기 (재시도 1/4)". **반응**: 처음엔 고장인 줄 앎 → 카운트다운을 보고 안심. 강사: "서버에도 한도가 있어요. 그래서 루프에 '기다렸다 다시'를 설계합니다."

### 장면 3 · 웹 손 꽂기 + 링크 읽기 (10분)

- [웹] 토글 → 손 목록에 `web_search`, `web_read` 추가. 처음 보는 `font-Pretendard.zip`을 다시 물으면 검색해서 답함.
- 링크 활동: 각자 좋아하는 디자이너 위키 링크를 주고 "3줄 요약".
- **오늘 시험에서 본 일이 그대로 나옴**: 같은 링크를 두 번 읽음. **강사**: "타임라인에 web_read가 두 번 있죠? 돈과 시간이 두 배. 루프 손잡이 '같은 호출 막기'를 켜 볼까요?" → 다시 보내면 한 번만 읽음. **이게 루프 엔지니어링을 몸으로 느끼는 순간.**
- **함정 체험(SHOULD)**: 없는 주소를 주면 모델이 "읽어 봤는데 안 됐다"고 말하지만 타임라인엔 도구 0번 → ⚠️ "말과 행동이 다름". **반응**: 놀라움 + 약간의 불신. 강사: "그래서 로그를 보는 습관이 중요해요. 에이전트를 믿는 게 아니라 확인하는 거예요."

### 장면 4 · 스킬 (12분)

- `SKILL.md` 빈칸 채우기. 디자인 전공답게 이름 규칙에 진심: "날짜_프로젝트_버전" vs "프로젝트-날짜".
- **반응**: 자기 문장대로 이름이 바뀌는 게 제일 반응이 큼. "내 말을 들었어!"
- 글 양 막대가 커지는 것 → "스킬이 길면 비싸고 느려진다"를 직관적으로.

### 장면 5 · 계획 + 승인 + 진짜 이동 (18분)

- 계획표 카드에서 ✅❌✏️💬. **학생 D**: ✏️로 이름을 하나 고치자 v2에서 비슷한 파일들도 같은 패턴으로 바뀜 → "오 따라 했어."
- **예상 문제**: GLM이 수정 하나를 과하게 따라 해서 엉뚱한 파일까지 바꿈(로그에서 이미 봄). **강사**: 이걸 숨기지 말고 보여 주기. "그래서 v2도 다시 심사해요. 사람이 끼는 자리가 왜 필요한지." 
- Finder에서 폴더가 진짜 바뀐 것 확인 → [되돌리기] → 원래대로. **반응**: "진짜로 옮겨지네" + 안도.
- **학생 E(Windows)**: 한글 파일명 깨짐 우려 → NFC 처리로 문제 없음(Mac 학생 쪽이 더 위험).

### 장면 6 · 도슨트 + 갤러리 (15분)

- Met에서 닮은 작품 + 위키 해설 → 갤러리 HTML. **반응**: 가장 큰 "오, 진짜 되네". 스크린샷 찍는 학생 다수.
- Cursor에게 "어두운 미술관 벽 느낌으로" → 템플릿만 바뀜.
- **예상 문제**: Met 공공 도메인 작품이 적어 "결과 없음" → 루프가 다른 검색어로 다시 시도하는 게 보임(이것도 루프).

### 장면 7 · 내 에이전트 스토리보드 (17분) / 마무리 (5분)

- 3~4시간차로 넘어갈 때 질문 예상: "제 아이디어는 사진을 찍으면… 이 키트로 돼요?" → 손 목록과 루프 손잡이 표를 보며 "이 손은 있고, 이 손은 없다(트랙 B)"로 판단.
