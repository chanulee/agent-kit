## 1. 수업 원칙

1. **사람이라면 어떻게 할까?** 개념마다 "사람 인턴이라면"으로 시작합니다.
2. **실패를 먼저 보여 줍니다.** 그다음 도구 하나로 뒤집습니다.
3. **자율성을 한 단계씩 올립니다.** 다이얼 0 → 4.
4. **학생은 거의 완성된 코드를 실행하고 관찰합니다.** 고치는 것은 config 한 줄, 한국어 파일, Cursor에게 하는 부탁 한 문장뿐입니다.
5. **(신규) 매 장면, 학생 손이 먼저 움직입니다.** 강사 시연은 3분 이내. 나머지는 학생이 직접 해 보고 화면으로 확인합니다.

자율성 다이얼:

| 단계 | 이름 | 누가 순서를 정하나 | 이 수업의 장면 |
|---|---|---|---|
| 0 | 챗봇 | 없음(말만 함) | 장면 0 |
| 1 | 고정 워크플로 | 코드 | 장면 1 |
| 2 | 도구를 고르는 에이전트 | LLM | 장면 2~4 |
| 3 | 계획 + 사람 승인 | LLM이 계획, 사람이 승인 | 장면 5 |
| 4 | 에이전트 둘이 나눠 일함 | LLM 둘 + 코드가 넘겨줌 | 장면 6 |

## 2. 학습 목표와 경험 아크

### 2.1 학습 목표 (L1~L4, 유지)

| # | 학생이 이해하고 느끼는 것 | 끝났을 때 학생이 하는 말 |
|---|---|---|
| L1 | AI는 말만 하는 뇌다. 손(도구)을 줘야 세상을 만진다. LLM은 고르기만 하고, 실행은 코드가 한다. | "아까 그 AI는 몰라서가 아니라 손이 없어서 틀린 거구나." |
| L2 | 에이전트는 고르고 → 해 보고 → 결과를 보고 → 다시 고르는 루프다. 언제 멈출지도 설계한다. | "결과를 보고 다음 걸 스스로 정하더라." |
| L3 | 에이전트 만들기의 대부분은 디자인이다. 손을 꽂고(MCP), 일하는 법을 적고(스킬), 길을 정하고(그래프), 사람이 끼어들 자리를 정한다(승인). | "내가 한국어로 쓴 규칙대로 움직였어. 그게 내 디자인이야." |
| L4 | (느낌) 내 진짜 파일로 진짜 결과가 나왔다. 내 아이디어에도 쓸 수 있겠다. | "오, 이게 진짜 되네? 내 에이전트는 이렇게 생겼어." |

### 2.2 선택한 아크: 탐정 → 큐레이터 → 도슨트

| 역할 | 하는 일 | 쓰는 손(도구) | 다이얼 |
|---|---|---|---|
| 🕵️ 탐정 | 사본 폴더를 뒤져 "폴더 주인은 어떤 사람인가"를 추리 | 읽기 도구 4개 → filesystem MCP | 2 |
| 🗂️ 큐레이터 | 전시실을 나누고, **내 이름 규칙(스킬)**으로 이름 바꾸기 계획을 세움. **내 승인 후 진짜로 옮김** | 스킬, `propose_plan`, `move_file` | 3 |
| 🎧 도슨트 | 전시실마다 메트로폴리탄 미술관에서 "닮은 명작"을 찾아 걸고, 웹에서 작품 이야기를 읽어 와 해설을 씀 | Met API 도구, **Fetch MCP**(웹 읽기) | 4 |

결과물: **「○○의 다운로드 전시회」 갤러리 HTML** + **진짜로 정리된 사본 폴더** + **내 에이전트 스토리보드와 다이어그램.**

### 2.3 사본 폴더: 진짜로 동작합니다

| 항목 | 방식 |
|---|---|
| 만들기 | `make_sandbox.py`가 원본 폴더에서 **진짜 복사**(`shutil.copy2`, 날짜 유지)합니다. 위치: `~/agent-workshop/exhibit_copy/`. 최대 60개, 파일당 20MB. |
| 고르기 | 복사 전에 목록을 보여 주고 학생이 뺄 파일을 고릅니다. 민감한 이름(신분증, 통장, 계약 등)은 기본 제외입니다. |
| 움직이기 | 승인된 항목만 **진짜로 이동·이름 변경**합니다. 학생은 Finder/탐색기에서 폴더가 바뀌는 것을 직접 봅니다. |
| 막는 것 | 사본 밖 경로 거부. 덮어쓰기 금지(충돌하면 `_2`). **삭제 도구는 없습니다.** |
| 되돌리기 | 모든 이동을 `undo.json`에 기록합니다. `python undo.py`로 원래대로 돌립니다. |
| 원본 | 한 번도 건드리지 않습니다. 원본에 적용할지는 집에서 학생이 직접 결정합니다. |

### 6.2 추천

1. **Fetch MCP를 전원에게.** 이유: 인증 없음, Node 불필요(uvx), 한 줄로 켬, 결과가 바로 해설에 들어감. 도슨트가 "위키백과에서 읽어 왔습니다(출처 링크)"라고 쓰면 웹 에이전트라는 느낌이 납니다. 주의: 미술관 웹페이지는 봇 확인 화면 때문에 못 읽습니다. **작품 데이터는 Met API로, 이야기는 위키백과로** 나눕니다.
2. **Playwright MCP는 강사 시연 + 원하는 학생만.** 이유: 화면에서 브라우저가 혼자 움직이는 장면은 가장 놀랍지만, 설치가 무겁고 16명이 동시에 쓰기엔 불안정합니다. 시연 시나리오: 도슨트가 작가의 위키백과 문서를 열고 → 스크롤 → 스크린샷을 찍어 갤러리에 붙임 [확인 필요: 리허설]. 실패하면 녹화 영상 30초로 대체합니다.

## 7. 도슨트는 "닮은 명작"을 어떻게 고르나

### 7.1 결론 먼저

- **기본은 텍스트(의미) 비교입니다. 비전은 쓰지 않습니다.** 파일 이름, 확장자, 날짜, 앞부분 텍스트 같은 **메타데이터에서 검색어를 만들고**, 미술관 작품의 **제목·분류·재료·태그**와 비교합니다.
- 그래서 "닮음"은 **주제와 분위기가 닮았다**는 뜻이지 **생김새가 닮았다**는 뜻이 아닙니다. 학생에게 이 점을 솔직하게 말합니다.
- **비전은 선택입니다.** 이미지 전시실에서 학생이 동의하면, 대표 이미지 1장(축소본)과 후보 작품 이미지를 Claude가 함께 보고 **색과 구도**로 다시 고릅니다. 이때 학생 이미지가 API로 전송됩니다.

### 7.2 4단계 (각 단계가 Loop Theater에 보입니다)

| 단계 | 누가 | 무엇을 | 입력 | 출력 | 화면 | 학생 개입 (H7) |
|---|---|---|---|---|---|---|
| D1 검색어 만들기 | 도슨트 LLM | 전시실 요약을 보고 **영어 검색어 3개**와 이유를 만듦 (Met 검색은 영어가 잘 됨) | 전시실 이름, 파일 수, 대표 파일명 5개, 확장자, 큐레이터 캡션. **파일 내용 원문은 보내지 않음** | `["poster", "typography", "sunflowers"]` + 이유 | **검색어 카드 3장** | 검색어 1개를 내 말로 고칠 수 있음 |
| D2 후보 찾기 | 코드(도구) | `met_search` 도구가 Met API 호출 | 검색어 | 후보 최대 8점 (제목, 작가, 연도, 재료, 분류, 태그, 이미지) | 후보 그리드 | — |
| D3 고르기 | 도슨트 LLM (+선택: 비전) | 후보를 전시실과 비교해 1점을 고르고 "왜 닮았나" 1문장 | 전시실 요약 + 후보 메타데이터 (+선택: 이미지) | 선택 1점 + 점수 + 이유 | **고른 작품에 테두리, 이유 표시** | 마음에 안 들면 다른 후보로 바꿈. 바꾼 기록은 도슨트에게 관찰로 돌아감 |
| D4 해설 쓰기 | 도슨트 LLM + Fetch MCP | 작품이나 작가의 위키백과 문서를 읽어 2~3문장 해설 | 작품 제목·작가 | 해설 + 출처 링크 | `tool.started fetch` → 웹 응답 | — |

### 7.3 D2의 실제 호출 [확인함, 2026-10-17 새벽]

1. `GET https://collectionapi.metmuseum.org/public/collection/v1.1/search?q=<검색어>&hasImages=true&limit=8` → 작품 ID 목록 (예: "sunflowers" 153건)
2. `GET https://collectionapi.metmuseum.org/public/collection/v1/objects/<id>` → `title`, `artistDisplayName`, `objectDate`, `medium`, `classification`, `department`, `tags`(용어 + Getty AAT/Wikidata 링크), `isPublicDomain`, `primaryImageSmall`, `objectURL`
3. **`isPublicDomain`이 true이고 `primaryImageSmall`이 있는 것만** 남깁니다. 예: 반 고흐 「Sunflowers」(436524)는 공공 도메인이고 이미지 주소가 열립니다(images.metmuseum.org 응답 200). 같은 검색의 다른 7점은 공공 도메인이 아니었습니다. → **후보가 금방 줄어듭니다.** 검색어 3개 × limit 8~20으로 넉넉히 찾습니다.
4. 옛 `/v1/search`는 "2026-10-01 종료" 메시지를 돌려줍니다. Cursor나 옛 튜토리얼이 v1 주소를 쓸 수 있으니 rules 파일에 v1.1을 명시합니다.
5. 호출 제한과 이미지 직접 연결 허용 여부는 [확인 필요]. 대비로 강사 PC에서 자주 나올 검색어 30개 결과를 미리 캐시합니다.

### 7.4 왜 이렇게 나누나 (수업 포인트)

- D1과 D3은 **LLM의 판단**, D2와 D4는 **도구의 실행**입니다. 장면 2에서 배운 "뇌는 고르고 손은 실행한다"가 그대로 다시 나옵니다.
- D1과 D3에 학생이 끼어들 수 있으니, 장면 5의 승인 경험을 **가볍게 한 번 더** 합니다.
- 장면 6의 "실패 먼저": 도구 없이 "이 전시실과 닮은 명작을 알려 줘"라고 하면 큐레이터가 **없는 작품이나 틀린 소장처를 지어냅니다.** 진짜 API를 붙이면 진짜 작품 ID와 이미지가 나옵니다.

공통 화면: 프로젝터 왼쪽은 강사 터미널, 오른쪽은 **Loop Theater**(design_2plus2.md C절. 턴 카드, 슬롯 다이어그램, 흐름 그래프, "LLM이 실제로 보는 것" 패널)를 띄웁니다. Theater 상단에 **자율성 다이얼**(0 챗봇 → 1 고정 워크플로 → 2 도구 고르기 → 3 계획+승인 → 4 에이전트 둘)을 추가해서 단계마다 바늘을 돌립니다.

### 0:00–0:05 (5분) 오프닝: 폴더 고백
- **강사 시연**: 강사 본인의 다운로드 폴더 스크린샷 공개("스크린샷 1,204개, 최종_진짜최종 9개"). "오늘 2시간 뒤 이 폴더가 전시회가 됩니다." 끝 화면(완성 갤러리)을 **3초만** 보여 주고 끕니다.
- **학생이 하는 것**: 손들기: "다운로드에 파일 500개 넘는 사람?"
- **화면 (Loop Theater)**: 완성 갤러리 3초 티저
- **아하**: "오늘은 코드 수업이 아니라 AI가 일하는 법을 들여다보는 수업"
- **안전**: 강사 파일만 사용

### 0:05–0:12 (7분) 장면 0. 똑똑한데 손이 없다 (챗봇의 한계)
- **사람이라면?**: 전화로만 일하는 천재 비서: 아는 건 많지만 내 방을 볼 수 없습니다.
- **강사 시연**: `--stage 0`(도구 없는 LLM). ① "지금 몇 시야?" → 모른다고 하거나 틀린 시각. ② "내 다운로드 폴더에 뭐 있어?" → "일반적으로 다운로드 폴더에는…" 일반론이나 **그럴듯한 가짜 파일 목록**(환각).
- **학생이 하는 것**: 자기 터미널에서 같은 두 질문. 가장 그럴듯한 거짓말을 한 사람 찾기
- **화면 (Loop Theater)**: 턴 카드 1장: `model.send → model.response`뿐. 슬롯 다이어그램에 "뇌"만 불 켜짐. 다이얼 0
- **아하**: **"AI는 몰라서 틀린 게 아니라, 볼 손이 없어서 틀린 거다."**
- **안전**: 아직 파일 접근 없음

### 0:12–0:24 (12분) 언플러그드 ① 인간 루프 연극 (루프의 정체)
- **사람이라면?**: (연극 자체가 비유)
- **강사 시연**: 4명이 무대로. 역할 카드: 🧠뇌(눈가리개, 메모만 씀), ✋손(메뉴판에 있는 일만 그대로 실행), 🌍세상(파일 카드 20장이 든 상자), 📜기록원(점점 길어지는 종이 띠 = messages). 미션: "이 상자에서 제일 오래된 파일을 찾아라." 뇌는 띠만 보고 "도구: 목록 보기" 카드를 냅니다 → 손이 실행 → 결과를 띠에 붙임 → 반복. 뇌가 "끝" 카드를 내면 종료. 턴 카드는 8장뿐(턴 한도).
- **학생이 하는 것**: 나머지는 4인 조로 똑같이 한 판(3분). 메뉴판에 없는 일을 시키면 손은 "못 해요"
- **화면 (Loop Theater)**: (Theater 끔. 칠판에 루프 그림 4칸)
- **아하**: **"뇌는 직접 아무것도 안 한다. 고르기만 하고, 결과를 보고, 다시 고른다. 이게 루프다."**

### 0:24–0:32 (8분) 장면 1. 고정 워크플로 (다이얼 1: 순서는 코드가 정함)
- **사람이라면?**: 신입 인턴에게 체크리스트를 줍니다: ①목록을 보고 ②확장자별로 세고 ③보고서를 쓴다. 인턴은 순서를 바꾸지 않습니다.
- **강사 시연**: `--stage 1`. 코드가 `list_files → count_by_type → LLM 요약` 순서로 **항상 같게** 돕니다. 강사 샘플 폴더로 실행 → "PDF 23, PNG 41, ZIP 9" 보고서. 그다음 "제일 큰 파일 3개 알려 줘"라고 하면 **못 합니다**(체크리스트에 없음).
- **학생이 하는 것**: **샘플 폴더**로 실행(아직 내 파일 아님). 체크리스트에 없는 질문 하나 해 보기
- **화면 (Loop Theater)**: 흐름 그래프에 고정된 3칸이 순서대로 불이 켜짐. LLM은 마지막 칸에서만 등장
- **아하**: **"믿을 만하지만 융통성이 없다. 순서를 AI에게 맡기면 어떻게 될까?"**
- **안전**: 읽기 전용, 샘플 폴더

### 0:32–0:47 (15분) 장면 2. 탐정: 도구를 스스로 고른다 (다이얼 2: 도구 사용 + 루프)
- **사람이라면?**: 탐정은 정해진 순서가 없습니다. 단서를 보고 다음에 어디를 볼지 정합니다.
- **강사 시연**: `--stage 2`. 이제 LLM에게 도구 메뉴(`list_files`, `file_info`, `peek_file`, `get_time`)를 줍니다. 먼저 장면 0의 질문 다시: "지금 몇 시야?" → `get_time` 호출 → 정답. **뒤집기 성공.** 이어서 탐정 미션: "이 폴더 주인은 어떤 사람일까? 단서 3개로 추리해 줘." → 에이전트가 목록 → 큰 파일 정보 → PDF 첫 페이지 엿보기 → … 5~10턴을 스스로 이어 갑니다. 마지막에 `max_turns: 3`으로 줄여 다시 실행 → 중간에 멈춤.
- **학생이 하는 것**: ① **내 사본 폴더**를 만들기(`python make_sandbox.py`, 4장/7장 참고. 싫으면 샘플 폴더). ② 탐정 미션 실행 → 추리 결과를 옆 사람과 비교. ③ config에서 `max_turns`를 3으로 바꿔 보기
- **화면 (Loop Theater)**: 턴 카드가 하나씩 쌓임. 도구 결과(`{"size": "1.2GB"}`)가 다음 턴의 선택을 바꾸는 장면. "LLM이 보는 것" 패널에서 messages가 매 턴 길어짐. 다이얼 2
- **아하**: **"순서를 내가 안 정했는데 알아서 다음 걸 골랐다. 그리고 결과를 보고 계획을 바꿨다."**
- **안전**: 도구가 **읽기 전용**. 텍스트 엿보기는 앞 500자, 민감 이름 파일 제외(7장)

### 0:47–0:57 (10분) 장면 3. MCP: 남이 만든 손을 꽂는다
- **사람이라면?**: 공구를 직접 만들지 않고, 표준 콘센트에 맞는 전동공구를 사서 꽂습니다. USB처럼요.
- **강사 시연**: config.yaml에서 주석 한 줄을 풀어 filesystem MCP 서버를 켭니다(사본 폴더 한정). 재시작하면 Theater 도구 패널에 도구가 4개에서 십여 개로 늘어납니다(`directory_tree`, `move_file`, `search_files`… [확인 필요: 현재 도구 이름]). "폴더 구조를 나무 모양으로 보여 줘" → `directory_tree`. 사본 밖 경로(`~/Desktop`)를 시키면 **서버가 거부**합니다.
- **학생이 하는 것**: 같은 한 줄을 풀고 재시작. 도구 개수 세기. 바깥 경로를 시켜 보고 거부되는 것 확인
- **화면 (Loop Theater)**: 슬롯 다이어그램에 "도구" 칸 옆으로 MCP 플러그 아이콘이 붙고 새 도구들이 들어옴. `mcp.connected` 이벤트
- **아하**: **"코드는 한 줄도 안 고쳤는데 손이 열 개가 됐다. 이게 MCP다."**
- **안전**: 서버 루트를 사본 폴더로 고정. Node가 없으면 aisuite 내장 files 툴킷으로 대체(7장)

### 1:05–1:20 (15분) 장면 4. 스킬: 일하는 법을 한국어로 적어 둔다
- **사람이라면?**: 회사 서랍 속 "업무 매뉴얼". 평소에는 서랍 라벨만 알고, 그 일을 할 때만 꺼내 읽습니다.
- **강사 시연**: `skills/` 폴더 소개. 시스템 프롬프트에는 스킬의 **이름과 한 줄 설명만** 들어갑니다. "전시실을 나눠 줘"라고 하면 LLM이 스스로 `load_skill("curator")`를 부르고, 그때 SKILL.md 본문이 들어옵니다. 실패 먼저: 스킬 없이 "이름 정리해 줘" → 제각각인 이름. 스킬을 넣으면 → `20261017_졸전_포스터_v03.png` 같은 일관된 이름.
- **학생이 하는 것**: **내 SKILL.md 쓰기(8분)**: 템플릿의 빈칸을 한국어로 채웁니다. ① 내 파일 이름 규칙 ② 전시실(카테고리) 4~6개와 기준 ③ 작품 캡션 말투(예: "미술관 캡션처럼 2문장, 약간 건방지게"). 저장하고 다시 실행
- **화면 (Loop Theater)**: `skill.loaded` 이벤트와 **컨텍스트 글자 수가 껑충 뛰는 막대**. 스킬이 필요 없는 질문("안녕")에는 안 뜸
- **아하**: **"코드가 아니라 내가 쓴 한국어 문장이 에이전트의 행동을 바꿨다."**
- **안전**: 아직 쓰기 없음. 이름은 '제안'만

### 1:20–1:37 (17분) 장면 5. 계획 → 승인 → 실행: 그래프와 사람 (다이얼 3: 계획 + 사람 개입)
- **사람이라면?**: 이사업체는 짐을 옮기기 전에 "이건 안방, 이건 창고" 견적서를 먼저 보여 주고 고객 사인을 받습니다. 순서는 정해져 있고, 사인이 없으면 트럭이 출발하지 않습니다.
- **강사 시연**: `--stage 5`. 흐름이 그래프로 바뀝니다: `탐색 → 분류 → 계획 작성(plan.json) → [승인 게이트] → 실행 → 전시`. 에이전트는 먼저 **dry-run 계획표**(현재 이름 → 새 이름 → 전시실, 이유)를 보여 주고 멈춥니다. 강사가 몇 줄은 ✅, 한 줄은 ❌("이건 건드리지 마") → 에이전트가 거절을 보고 대안을 냅니다. 승인된 것만 옮기고 `undo.json`을 남깁니다. 마지막에 `python undo.py`로 **되돌리기** 시연.
- **학생이 하는 것**: 내 사본으로 계획 받기 → 계획표를 **직접 읽고** 최소 1줄은 거절해 보기 → 승인 → 사본 폴더를 파인더/탐색기로 열어 실제로 바뀐 것 확인
- **화면 (Loop Theater)**: 흐름 그래프에서 현재 노드에 불이 들어오고 **승인 게이트에서 노란 배너로 멈춤**. ✅/❌ 기록. 다이얼 3
- **아하**: **"AI가 얼마나 마음대로 할지는 다이얼이고, 사람이 끼어들 자리를 정하는 게 내 디자인이다."**
- **안전**: 미리보기 먼저, 승인 전 쓰기 0. 이동은 사본 안에서만. 덮어쓰기 금지(이름 충돌 시 `_2`). 삭제 도구는 아예 없음. 되돌리기 로그

### ↳ 승인 게이트 몸으로 하기 (장면 5 안에서 3분)
- **강사 시연**: 바닥에 테이프로 노드 5칸. 한 학생이 "에이전트"가 되어 칸을 걸어가고, 게이트 칸에는 빨강/초록 도장을 든 "사람"이 서 있습니다. 도장 없이는 다음 칸으로 못 갑니다.
- **학생이 하는 것**: 관객이 "여기도 게이트가 필요해!"라고 외치면 게이트 추가
- **아하**: **"게이트를 몇 개 둘지가 곧 신뢰의 설계."**

### 1:37–1:52 (15분) 장면 6. 피날레: 에이전트 둘, 그리고 진짜 인터넷 (다이얼 4: 멀티에이전트 + 웹 서비스)
- **사람이라면?**: 큐레이터가 전시실을 꾸리면, 도슨트가 각 방에 맞는 이야기와 비교 작품을 찾아옵니다. 각자 잘하는 일이 다릅니다.
- **강사 시연**: `--stage 6`. **큐레이터 에이전트**가 전시실과 캡션을 만들고 `exhibit.json`을 넘기면, **도슨트 에이전트**(다른 페르소나, 다른 도구)가 메트로폴리탄 미술관 Open Access API에서 전시실마다 **"닮은 명작"** 한 점을 찾아 겁니다(공공 도메인 이미지만). 마지막으로 `render`가 **「○○의 다운로드 전시회」 갤러리 HTML**을 엽니다. 이어서 보너스 3분: 브라우저 MCP로 에이전트가 웹을 직접 돌아다니는 모습 시연(아크 B 맛보기).

- **아하**: **"오, 이게 진짜 되네? 내 '최종_최종.pdf' 옆에 고흐가 걸려 있어."**

## 9. [v0.3] 집에 가져가는 결과물과 그 다음

학생이 가져가는 것(모두 `my_exhibit/` 폴더 하나에):

1. **「○○의 다운로드 전시회」 `exhibit.html`**: 전시실, 파일 썸네일(이미지 파일만), 큐레이터 캡션, 도슨트가 건 "닮은 명작"(공공 도메인 이미지 + 출처 링크), 맨 앞 "큐레이터의 글"(탐정 추리 결과). 오프라인으로 열립니다.
2. **정리된 사본 폴더 + `plan.json` + `undo.json`**: 원본은 그대로입니다. 마음에 들면 집에서 계획표를 보고 원본에 적용할지 **본인이** 결정합니다(적용 스크립트는 제공하지 않고 손으로 하라고 권합니다. 7장 참고).
3. **내가 쓴 `skills/curator/SKILL.md`와 `persona.md`**: 내 이름 규칙과 내 말투. 이게 **내 에이전트의 첫 부품**입니다.
4. **Loop Theater 리플레이 `trace.jsonl`**: 내 에이전트가 생각한 과정 전체. 친구에게 "AI가 내 폴더를 이렇게 뒤졌다"를 다시 보여 줄 수 있습니다.
5. **워크시트 1장**: 자율성 다이얼, "내 에이전트에 줄 손·매뉴얼·게이트".

3~4시간차로 이어지는 방법:

- 엔진(`agent/loop.py`, 그래프, 승인, Theater)은 그대로 두고, **재료와 부품만 바꿉니다.** 다운로드 폴더 자리에 내 아이디어의 재료를 넣고, 같은 SKILL.md 형식으로 내 스킬을 쓰고, 승인 자리를 내 아이디어에 맞게 바꿉니다.

핵심 도구 설계 메모:

- `peek_file(path)`: 텍스트/마크다운은 앞 500자, PDF는 첫 페이지 텍스트 앞 500자(pypdf), 이미지는 크기·해상도만(비전은 옵션, 기본 끔), 나머지는 메타데이터만.
- `propose_plan(...)`: **쓰지 않고** `plan.json`만 만듭니다. `apply_move(plan_id)`만 쓰기 도구이며 `require_approval` 목록에 있습니다.
- aisuite 내장 files 툴킷(`aisuite.toolkits.files(root=..., allow_write=...)`)에는 `list_files`, `read_file`, `search_files`, `write_file` 등은 있지만 **이동/이름 바꾸기 도구가 없습니다** [소스 확인]. 그래서 `apply_move`는 직접 만들고, 삭제 도구는 어디에도 만들지 않습니다.
- `met_search(keyword)`: Met Collection API `GET /public/collection/v1.1/search?q=...&hasImages=true&limit=8` → `GET /public/collection/v1/objects/{id}`에서 `isPublicDomain=true`이고 `primaryImageSmall`이 있는 것만 고릅니다. **[확인함, 2026-10-17 00:50 KST]**: 예전 `/v1/search`는 "2026-10-01에 종료되었다"는 메시지를 돌려주고, v1.1은 동작합니다(예: "sunflowers" 153건, 공공 도메인 이미지 확인). 키는 필요 없습니다. 호출 제한은 [확인 필요]. Cursor나 옛 튜토리얼은 v1 주소를 쓸 수 있으니 rules 파일에 명시합니다.
