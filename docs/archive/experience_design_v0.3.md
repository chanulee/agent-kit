## 0. 왜 다시 짜는가 (강사 피드백 요약)

- 지금 안(오늘도감 Stage 0→6)은 **"제 코드 따라 치세요, 뼈대 만드세요"** 수업입니다. 디자인 전공 3·4학년에게는 지루하고, 끝에 남는 것도 "항목 몇 개 저장된 JSON"입니다.
- 「오늘도감」은 **데이터가 없습니다.** 수업 중에 하루를 기록할 거리가 없으니, 가짜 입력을 치게 됩니다.
- 학생들이 아는 것은 "Cursor/AI에게 말하면 된다"뿐이고, **에이전트가 무엇인지 전혀 모릅니다.** 목표는 파이썬이 아니라 **에이전트가 움직이는 원리(루프, 도구, 그래프, MCP, 스킬)와 이걸로 무엇을 할 수 있는지**를 이해하는 것입니다.
- 그래서 2시간을 **하나의 경험**으로 설계합니다. 개념을 한 번에 하나씩 꺼내고, 끝에는 **학생 자기 파일**로 동작하는 놀라운 결과물이 나와서 "오, 이게 진짜 되네? 신기하네?"라는 말이 나오게 합니다.

수업 설계 원칙(Andrew Ng 코스 방식 적용):

1. **사람이라면 어떻게 할까?** 개념마다 먼저 "사람 인턴이라면 이 일을 어떻게 할까"로 시작합니다. 에이전트 설계는 일하는 사람의 과정을 설계하는 것입니다.
2. **실패를 먼저 보여 줍니다.** "지금 몇 시야?", "내 다운로드 폴더에 뭐 있어?"에 AI가 모른다고 하거나 지어내는 것을 먼저 봅니다. 그다음 **도구 하나**를 주면 결과가 뒤집힙니다.
3. **자율성을 한 단계씩 올립니다.** 정해진 순서(고정 워크플로) → LLM이 도구를 고름 → LLM이 계획을 세우고 사람이 승인 → 에이전트 둘이 일을 나눔. 화면의 "자율성 다이얼"이 한 칸씩 올라갑니다.
4. **거의 완성된 스타터 코드를 줍니다.** 학생은 파이썬을 치지 않습니다. 고치는 것은 `config.yaml`의 한 줄, 한국어로 쓴 `SKILL.md`, `persona.md`, 그리고 원하면 Cursor에게 하는 부탁 한 문장뿐입니다. 나머지 시간은 **보는 데** 씁니다.

## 1. 학습 목표 (학생이 무엇을 이해하고 느끼는가)

| # | 학생 입장의 목표 | 끝났을 때 학생이 할 수 있는 말 |
|---|---|---|
| L1 | **AI는 말만 하는 뇌이고, 손(도구)을 줘야 세상을 만질 수 있다.** LLM은 아무것도 실행하지 않고 "이 도구를 이렇게 써 줘"라고 고르기만 하며, 실행은 코드가 한다. | "아까 그 AI는 내 폴더를 못 본 게 아니라 볼 손이 없었던 거구나." |
| L2 | **에이전트는 고르고, 해 보고, 결과를 보고, 다시 고르는 루프다.** 도구 결과가 다음 행동을 바꾸고, 언제 멈출지(턴 한도)도 설계해야 한다. | "Theater 화면에서 턴이 쌓이는 걸 봤어. 결과를 보고 다음 걸 스스로 정하더라." |

| L4 | **(느낌) 내 진짜 파일로 진짜 결과가 나왔다. 그리고 내 아이디어에도 이걸 쓸 수 있겠다.** | "내 다운로드 폴더가 전시회가 됐어. 3~4시간차에는 이걸로 내 에이전트를 만들 거야." |

## 2. 경험 아크 후보 3개와 선택

### 아크 A. 「다운로드 폴더 탐정 → 큐레이터」 (선택)

- 줄거리: 내 다운로드(또는 학교 과제) 폴더의 **사본**을 에이전트에게 줍니다. 에이전트는 처음에는 **탐정**이 되어 파일을 뒤져 "이 폴더 주인은 어떤 사람인가"를 추리하고, 다음에는 **큐레이터**가 되어 파일을 전시실(카테고리)로 나누고, **내가 정한 이름 규칙**으로 이름 바꾸기 계획을 세우고, **내 승인**을 받아 옮긴 뒤, 마지막으로 **「○○의 다운로드 전시회」 HTML 갤러리**(전시실, 작품 캡션, 큐레이터의 글)를 만듭니다.
- 피날레 반전: 두 번째 에이전트 **도슨트**가 진짜 웹 서비스(메트로폴리탄 미술관 Open Access API)에 접속해서 **"내 파일과 닮은 명작"**을 전시실마다 하나씩 걸어 둡니다. "최종_진짜최종_v3.psd 옆에 반 고흐가 걸려 있다."
- 장점: 데이터가 **이미 학생 PC에 있고**, 대부분 엉망이라 웃깁니다(`스크린샷 2026-...png` 400개, `최종_최종.pdf`). 파일 이름과 분류는 **디자이너가 실제로 아끼는 주제**입니다. 쓰기 행동(이름 바꾸기, 옮기기)이 실제로 있어서 **승인이 꼭 필요한 이유**가 저절로 생깁니다. 탐정 단계는 읽기만 하므로 안전하게 시작할 수 있습니다.
- 단점: 개인 파일 프라이버시(7장에서 대응), Windows/Mac 경로 차이, 파일 수가 많으면 비용과 시간이 늘어남(사본은 최대 60개로 제한).

### 아크 B. 「레퍼런스 헌터」 (브라우저 중심)

- 줄거리: "졸업 전시 무드보드 만들어 줘" → 에이전트가 Playwright 브라우저 MCP로 웹을 직접 돌아다니며 레퍼런스를 모으고 무드보드 페이지를 만듭니다. 화면에서 브라우저가 혼자 움직이는 모습이 아주 인상적입니다.
- 단점: 16명이 동시에 브라우저를 띄우면 느리고 불안정합니다. 사이트가 봇을 막거나 쿠키 팝업에서 멈추는 일이 잦습니다. 결과물이 "남의 이미지 모음"이라 **내 것**이라는 느낌이 약하고, 저작권 문제도 있습니다. Playwright MCP 설치(브라우저 바이너리 다운로드)도 오래 걸립니다 [확인 필요].
- 쓰는 법: **강사 시연 3분**(Stage 6 직후 "이런 손도 꽂을 수 있다")과 3~4시간차 선택 모듈로만 씁니다.

### 아크 C. 「내 작업 × 진짜 서비스」 (웹 API 중심)

- 줄거리: 내 포트폴리오 폴더의 작업 이미지를 Claude 비전으로 읽고, 미술관 API에서 닮은 작품을 찾아 "내 작업의 족보" 페이지를 만듭니다.
- 장점: 결과가 감동적이고 API는 키가 필요 없습니다.
- 단점: 이미지 비전 호출 비용과 시간이 들고, 탐색/정리/승인 같은 **루프와 쓰기 행동이 약합니다.** 개념을 차례로 보여 주기에는 단계가 적습니다.
- 쓰는 법: 아크 A의 **피날레(도슨트 에이전트)**로 흡수합니다.

### 선택: 아크 A + C의 피날레 (+ B는 3분 시연)

이유:
1. **개념이 순서대로 나옵니다.** 읽기만 하는 탐정(도구, 루프) → 손을 더 꽂기(MCP) → 내 이름 규칙(스킬) → 계획과 승인(그래프, 사람 개입) → 에이전트 둘(멀티에이전트) → 진짜 웹 서비스. 자율성 다이얼을 한 칸씩 올리는 흐름과 그대로 맞습니다.
2. **실패 → 뒤집기가 극적입니다.** "내 다운로드에 뭐 있어?"는 어떤 챗봇도 답하지 못하는 질문이고, 도구 하나로 바로 답하게 됩니다.
3. **안전하게 위험을 가르칠 수 있습니다.** 진짜 파일을 옮기는 일이라 "승인 없이 옮기면 어떻게 될까?"를 학생이 직접 느낍니다. 사본 폴더, 미리보기(dry-run), 되돌리기, 삭제 도구 없음으로 실제 사고는 막습니다.
4. **집에 가져갈 결과물이 자랑할 만합니다.** 내 폴더로 만든 전시회 페이지는 친구에게 보여 주고 싶어집니다.
5. **3~4시간차로 바로 이어집니다.** "나만의 에이전트" 아이디어는 흔히 "남기기 → 해석하기 → 쌓기 → 보여 주기" 구조(docs/04 9장)인데, 이 아크가 정확히 그 구조를 **진짜 데이터로** 보여 줍니다.

### 0:00–0:05 (5분) 오프닝: 폴더 고백
- **강사 시연**: 강사 본인의 다운로드 폴더 스크린샷 공개("스크린샷 1,204개, 최종_진짜최종 9개"). "오늘 2시간 뒤 이 폴더가 전시회가 됩니다." 끝 화면(완성 갤러리)을 **3초만** 보여 주고 끕니다.
- **학생이 하는 것**: 손들기: "다운로드에 파일 500개 넘는 사람?"
- **화면 (Loop Theater)**: 완성 갤러리 3초 티저
- **아하**: "오늘은 코드 수업이 아니라 AI가 일하는 법을 들여다보는 수업"
- **안전**: 강사 파일만 사용

### 0:05–0:12 (7분) 장면 0. 똑똑한데 손이 없다 (챗봇의 한계)
- **사람이라면?**: 전화로만 일하는 천재 비서: 아는 건 많지만 내 방을 볼 수 없습니다.
- **강사 시연**: `--stage 0`(도구 없는 LLM). ① "지금 몇 시야?" → 모른다고 하거나 틀린 시각. ② "내 다운로드 폴더에 뭐 있어?" → "일반적으로 다운로드 폴더에는…" 일반론이나 **그럴듯한 가짜 파일 목록**(환각).
- **학생이 하는 것**: 자기 터미널에서 같은 두 질문. 가장 그럴듯한 거짓말을 한 사람 찾기
- **화면 (Loop Theater)**: 턴 카드 1장: `model.send → model.response`뿐. 슬롯 다이어그램에 "뇌"만 불 켜짐. 다이얼 0
- **아하**: **"AI는 몰라서 틀린 게 아니라, 볼 손이 없어서 틀린 거다."**
- **안전**: 아직 파일 접근 없음

## 4. 언플러그드 / 몸으로 하는 활동 (디자이너용)

| 활동 | 언제 | 준비물 | 방법 | 가르치는 개념 |
|---|---|---|---|---|
| **① 인간 루프 연극** | 0:12 | 역할 목걸이 4종(🧠뇌, ✋손, 🌍세상, 📜기록원), 눈가리개, 파일 카드 20장(가짜 파일명·크기·날짜 인쇄), 도구 메뉴판, 종이 띠(롤), 턴 카드 8장, "끝" 카드 | 뇌는 띠만 볼 수 있고 메뉴판에서만 주문합니다. 손은 주문 그대로만 실행하고 결과를 쪽지로 띠에 붙입니다. 턴 카드가 떨어지면 강제 종료. | 루프, 도구 스키마, messages(맥락), 종료 조건, 턴 한도 |

| **③ 플러그 봉투 (MCP)** | 0:47 | "filesystem 서버"라고 적힌 봉투 안에 메뉴판 8장 | 봉투를 꽂으면 메뉴판이 한꺼번에 늘어남. 봉투에는 "이 상자 밖은 못 만짐" 스티커 | MCP = 남이 만든 도구 묶음 + 범위 제한 |

| **⑤ 바닥 그래프 + 승인 도장** | 1:20 | 마스킹테이프, 노드 이름표 5장, 빨강/초록 도장 | 에이전트 역 학생이 노드를 걸어가고, 게이트에서 도장을 받아야 진행 | 그래프(정해진 길과 갈림길), Human-in-the-loop |
| **⑥ 자율성 다이얼 스티커** | 매 장면 | 워크시트의 0~4 다이얼 그림 | 장면마다 "지금 AI가 얼마나 마음대로 하나"에 바늘을 그림. 마지막에 "내 기획은 몇 번?"에 표시 | 자율성의 정도(Ng 코스 "Degrees of autonomy") |

## 5. 집에 가져가는 결과물과 그 다음

학생이 가져가는 것(모두 `my_exhibit/` 폴더 하나에):

1. **「○○의 다운로드 전시회」 `exhibit.html`**: 전시실, 파일 썸네일(이미지 파일만), 큐레이터 캡션, 도슨트가 건 "닮은 명작"(공공 도메인 이미지 + 출처 링크), 맨 앞 "큐레이터의 글"(탐정 추리 결과). 오프라인으로 열립니다.
2. **정리된 사본 폴더 + `plan.json` + `undo.json`**: 원본은 그대로입니다. 마음에 들면 집에서 계획표를 보고 원본에 적용할지 **본인이** 결정합니다(적용 스크립트는 제공하지 않고 손으로 하라고 권합니다. 7장 참고).
3. **내가 쓴 `skills/curator/SKILL.md`와 `persona.md`**: 내 이름 규칙과 내 말투. 이게 **내 에이전트의 첫 부품**입니다.
4. **Loop Theater 리플레이 `trace.jsonl`**: 내 에이전트가 생각한 과정 전체. 친구에게 "AI가 내 폴더를 이렇게 뒤졌다"를 다시 보여 줄 수 있습니다.
5. **워크시트 1장**: 자율성 다이얼, "내 에이전트에 줄 손·매뉴얼·게이트".

3~4시간차로 이어지는 방법:

- 엔진(`agent/loop.py`, 그래프, 승인, Theater)은 그대로 두고, **재료와 부품만 바꿉니다.** 다운로드 폴더 자리에 내 아이디어의 재료를 넣고, 같은 SKILL.md 형식으로 내 스킬을 쓰고, 승인 자리를 내 아이디어에 맞게 바꿉니다.

## 6. 스타터 키트 (오늘 밤 준비, 최소한으로)

원칙: **거의 완성된 코드**. 학생은 실행하고 관찰하고, config/한국어 파일만 고칩니다. 모든 Stage 완성본이 미리 들어 있어서 `--stage N`만 바꾸면 됩니다.

```
download-exhibit/
├─ README.md               # 설치 3단계 + 문제 해결 (Windows/Mac 나란히)
├─ pyproject.toml, uv.lock # aisuite==0.2.0 + anthropic extras [확인 필요], python-dotenv, pyyaml
├─ .env.example            # ANTHROPIC_API_KEY= 만
├─ config.yaml             # model, max_turns, sandbox_path, mcp_servers(주석 처리), require_approval
├─ run.py                  # python run.py --stage 0..6
├─ make_sandbox.py         # 원본 폴더 → data/sandbox/ 로 '복사'(최대 60개, 파일당 20MB, 제외 규칙)
├─ undo.py                 # undo.json으로 사본 되돌리기
├─ agent/  loop.py · trace.py · graph.py · policy.py · skills.py · mcp.py   # 학생은 안 고침
├─ tools/  basic.py(get_time) · files.py(list_files, file_info, peek_file) · plan.py(propose_plan, apply_move) · met.py(met_search)
├─ skills/curator/SKILL.md # 빈칸 템플릿 (이름 규칙, 전시실, 캡션 말투)
├─ personas/ curator.md · docent.md
├─ render/exhibit.py + exhibit_template.html   # 갤러리 HTML
├─ sample_downloads/       # 가상의 디자인과 학생 "김디자"의 엉망 다운로드 40개 (프라이버시 대체용, 재미있게)
├─ viz/                    # Loop Theater (design_2plus2.md C절) + replays/stage0~6.jsonl
├─ .cursor/rules/workshop.mdc  # "agent/ 수정 금지, 삭제 기능 추가 금지, Met API는 v1.1 search 사용"
└─ print/ cards.pdf        # 역할 목걸이, 파일 카드 20장, 메뉴판, 봉투 라벨, 워크시트
```

오늘 밤 작업 우선순위(약 4시간 예상, 순서대로 하다 멈춰도 수업이 됨):

1. **(60분) Stage 0, 2, 5 동작**: 루프 + 읽기 도구 + 계획/승인/이동/되돌리기. 이 셋이 수업의 뼈대입니다. aisuite 수동 루프에서 Anthropic `tool_calls` 형식을 가장 먼저 확인합니다 [확인 필요, design_2plus2.md E-1].
2. **(40분) `make_sandbox.py` + `sample_downloads/`**: Windows/Mac 다운로드 경로 자동 탐지, 한글 파일명 정규화(NFC), 제외 규칙.
3. **(40분) Stage 6**: `met_search` 도구 + 도슨트 페르소나 + `exhibit.html` 템플릿.
4. **(40분) Loop Theater 최소 기능 + 리플레이 녹화** (stage0~6 각각 강사 샘플 폴더로 1회씩 녹화).
5. **(20분) Stage 1, 3, 4**: 고정 워크플로, MCP 한 줄, 스킬 로더.
6. **(20분) 인쇄물**: 카드, 메뉴판, 워크시트. 인쇄가 안 되면 화면 카드로 대체.
7. 내일 아침 학생 공지: "노트북, 충전기, 그리고 **다운로드 폴더를 지우지 말고 그대로** 가져오세요. 보여 주기 싫은 파일이 있으면 샘플 폴더를 쓰면 됩니다." + Node 20 설치 확인(선택).

핵심 도구 설계 메모:

- `peek_file(path)`: 텍스트/마크다운은 앞 500자, PDF는 첫 페이지 텍스트 앞 500자(pypdf), 이미지는 크기·해상도만(비전은 옵션, 기본 끔), 나머지는 메타데이터만.
- `propose_plan(...)`: **쓰지 않고** `plan.json`만 만듭니다. `apply_move(plan_id)`만 쓰기 도구이며 `require_approval` 목록에 있습니다.
- aisuite 내장 files 툴킷(`aisuite.toolkits.files(root=..., allow_write=...)`)에는 `list_files`, `read_file`, `search_files`, `write_file` 등은 있지만 **이동/이름 바꾸기 도구가 없습니다** [소스 확인]. 그래서 `apply_move`는 직접 만들고, 삭제 도구는 어디에도 만들지 않습니다.
- `met_search(keyword)`: Met Collection API `GET /public/collection/v1.1/search?q=...&hasImages=true&limit=8` → `GET /public/collection/v1/objects/{id}`에서 `isPublicDomain=true`이고 `primaryImageSmall`이 있는 것만 고릅니다. **[확인함, 2026-10-17 00:50 KST]**: 예전 `/v1/search`는 "2026-10-01에 종료되었다"는 메시지를 돌려주고, v1.1은 동작합니다(예: "sunflowers" 153건, 공공 도메인 이미지 확인). 키는 필요 없습니다. 호출 제한은 [확인 필요]. Cursor나 옛 튜토리얼은 v1 주소를 쓸 수 있으니 rules 파일에 명시합니다.
