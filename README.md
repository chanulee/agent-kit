# agent-kit: 디자인 전공생을 위한 에이전트 워크숍 키트

디자인 전공 3·4학년 약 16명이 4시간 동안 "에이전트가 어떻게 움직이는지" 직접 겪어 보는 워크숍의 **설계 문서와 기술 검증 코드**입니다.

- 1~2시간차: 모두 같은 에이전트 **「내 다운로드 폴더 전시회」**를 함께 겪습니다. 코딩 수업이 아니라 체험입니다.
- 3~4시간차: 각자 자기 에이전트를 만듭니다. 부품 바꾸기, 다이어그램 + 부분 시제품, 오즈의 마법사 중 하나를 고릅니다.

## 쉬운 말로 먼저

| 말 | 한 줄 뜻 |
|---|---|
| 에이전트 | 목표를 받으면 스스로 할 일을 고르고, 실제로 해 보고, 결과를 보고 다음 일을 정하는 AI |
| 도구 | 에이전트의 "손". 예: 파일 목록 보기, 웹 검색 |
| 루프 | "고르기 → 해 보기 → 결과 보기 → 다시 고르기"를 되풀이하는 것 |
| MCP | 남이 만든 손을 꽂는 표준 콘센트 |
| 스킬 | 필요할 때만 꺼내 읽는 업무 매뉴얼(`SKILL.md`) |
| API | 프로그램끼리 정보를 주고받는 창구. 예: 미술관 작품 목록 |
| 하네스 | AI를 감싸서 실제로 일하게 하는 틀(루프, 도구 연결, 기록, 허락 받기) |

더 자세한 풀이: [docs/00_glossary.md](docs/00_glossary.md)

## 문서 규칙

- **최신 결정이 우선합니다.** `docs/01~06`이 기준이고, `docs/archive/`는 참고용입니다.
- **[확인함]**: 직접 실행해서 확인한 것. **[확인 필요]**: 문서나 소스만 보고 아직 실행하지 않은 것.
- 개별 학생의 정보나 기획은 담지 않습니다. 예시는 모두 설명을 위해 지어낸 것입니다.
- API 키와 `.env` 값은 이 저장소에 넣지 않습니다. 키는 내 컴퓨터의 환경 변수(`.env` 파일)에서만 읽습니다.

## 한 줄 요약

> 거의 완성된 스타터 앱에서 버튼을 켜고 끄며 에이전트의 자율성을 L1(챗봇) → L4(에이전트 둘)까지 올려 보고, 그 버튼이 사실은 `config.yaml`, `persona.md`, `SKILL.md`, `mcp.json` 한 줄이라는 것을 알게 되는 수업.
