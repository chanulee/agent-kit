# agent-kit: 디자인 전공생을 위한 에이전트 워크숍 키트

디자인 전공 3·4학년이 에이전트가 어떻게 움직이는지 직접 보는 워크숍 키트입니다.

앞의 2시간은 모두 **에이전트 하나**를 키웁니다. 이름은 `agents/my-agent`. 단계마다 설정에 줄이 하나씩 늘고, 그 줄은 화면의 **🧩 부품**에서 켜거나 파일을 고쳐 바꿉니다. 단계 폴더는 없습니다.

뒤의 2시간은 그 에이전트를 자기 작업으로 바꿔 봅니다. 부품을 바꾸거나, 그림으로 설계하거나, 사람이 뒤에서 대신 답하는 방식 중 하나를 고릅니다.

## 0. 준비

1. 이 저장소를 받습니다. `git clone`, 또는 GitHub에서 Code → Download ZIP.
2. [uv](https://docs.astral.sh/uv/)를 한 번 설치합니다.
   - Mac: 터미널에 `curl -LsSf https://astral.sh/uv/install.sh | sh`
   - Windows: PowerShell에 `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`
3. `.env.example`을 복사해 이름을 `.env`로 바꿉니다. 두 칸에 키를 붙여 넣습니다.
   - `ZAI_API_KEY` — 모델 (Z.ai)
   - `TAVILY_API_KEY` — 웹 검색. 키만 넣거나, Tavily가 준 MCP 주소 전체를 넣어도 됩니다.
4. 키트 폴더에서 `uv run app.py`
5. 브라우저에 대시보드가 열립니다. 위쪽에 **모델 연결됨**, **Tavily 키 있음**이 보이면 준비가 된 것입니다. 웹 검색 스위치 자체는 5단계에서 켭니다.
6. **📁 폴더 고르기** → 샘플 폴더(또는 내 폴더) → 사본 만들기. 에이전트는 이 사본만 봅니다. 원본은 그대로입니다.

끄려면 터미널에서 Ctrl+C.

## 화면 세 칸

| 칸 | 무엇을 보나 |
|---|---|
| 💬 대화 | 에이전트가 한 말. 승인 카드와 오류 카드(어느 단계인지, 무슨 일인지, 무엇을 하면 되는지)도 여기 |
| 🔁 루프 | 에이전트가 한 행동. 턴마다 🧠 생각 → 🔧 도구 → 결과. 팀 실행에서는 에이전트마다 칸이 나뉘고, 가운데 **넘겨주기**가 보입니다 |
| 🧩 부품 | 도구, 스킬, MCP, 승인(✋), 루프 조절. 켜면 `agents/my-agent/agent.yaml` 또는 `mcp.json` 한 줄이 바뀝니다. 파일을 직접 고쳐도 몇 초 안에 화면이 따라옵니다 |

위의 **👥 팀 실행**은 6단계입니다. 나의 에이전트가 먼저 일하고, 준비된 도슨트가 이어서 갤러리를 만듭니다.

## 폴더 지도

```
app.py                      대시보드를 켜는 파일. 학생은 보통 여기만 실행합니다
config.yaml                 누구와 대화할지(my-agent), 팀 짝(docent), 모델 이름, 사본 폴더 위치
mcp.json                    웹 검색(Tavily MCP)을 켜고 끄는 파일. 주소도 여기 있습니다
.env                        키. 저장소에 올리지 않습니다. .env.example 이 빈 칸입니다

agents/my-agent/            학생이 키우는 에이전트. 처음에는 말만 합니다
  agent.yaml                도구 목록, 스킬, 승인, 턴 한도
  persona.md                위는 기본 규칙(미리 적힘), 아래는 성격·말버릇(학생이 적음)
agents/docent/              팀 실행용으로 미리 만들어 둔 도슨트. 갤러리를 맡습니다

tools/                      도구. 함수 하나가 할 수 있는 일 하나
  files.py                  폴더 목록, 앞부분 보기, 파일 정보
  move.py                   정리 계획, 파일 옮기기, 되돌리기
  write.py                  마크다운 노트 만들기
  web.py                    웹 검색·페이지 읽기. 접속 주소는 mcp.json 에서 읽습니다
  met.py                    메트로폴리탄 미술관 공개 API. 작품 정보와 갤러리 HTML은 코드가 채웁니다
  clock.py                  지금 시각
  gallery_template.html     갤러리 페이지의 모양

skills/curator/SKILL.md         폴더를 전시실로 나누는 규칙
skills/research-note/SKILL.md   리서치 노트의 구성 (요약, 핵심, 출처 표, 더 물어볼 질문)

engine/                     루프, 승인, 화면. 수업 중에는 고치지 않습니다
sample_downloads/           연습용으로 만들어 둔 가짜 다운로드 폴더
tests/test_kit.py           키 없이 도는 시험. `uv run pytest`
docs/                       수업 설계 메모. 지금 키트의 기준은 이 README입니다
prototype/                  키트를 만들기 전에 돌렸던 기술 확인 스크립트
```

실행하면 `runs/<시간>/trace.jsonl`에 루프 기록이 쌓입니다. 이 폴더는 git에 올라가지 않습니다.

## 2시간 흐름 — 무엇을 켜나

말하기 전에 **사본 폴더**를 만들어 두세요. 아래의 "파일에 생기는 줄"은 화면에서 켜도 같은 자리가 바뀝니다.

### 1. 챗봇 — 모델과 성격만

부품은 비어 있습니다. `agents/my-agent/agent.yaml`의 `tools:`는 `[]`입니다.

`persona.md`는 두 부분입니다.

- **기본 규칙** — 미리 적혀 있습니다. 한국어로 답하기, 도구 결과에 있는 것만 사실로 말하기, 도구를 쓰지 않았으면 "읽어 봤다"고 말하지 않기.
- **성격·말버릇** — 학생이 적습니다. 존댓말, 짧은 답, 말투 같은 것.

폴더를 볼 도구가 없으므로, "이 폴더 주인은 누구야?"라고 물으면 모른다고 하거나 짐작으로 지어냅니다. 🔁 루프에는 도구 줄이 없습니다.

### 2. 도구 — 폴더를 보고 주인을 추리

🧩에서 폴더 보기의 세 개를 켭니다.

- `list_files` — 파일 목록. 각 파일에 번호가 붙습니다
- `peek_file` — 글 파일의 앞부분, 그림은 크기만
- `file_info` — 종류, 크기, 수정한 날

파일에는 이렇게 들어갑니다.

```yaml
tools: [list_files, peek_file, file_info]
```

다시 주인 추리를 시키면, 루프에서 생각 → 도구 → 결과 → 다시 생각이 보입니다. 번호로 파일을 집어 봅니다.

### 3. 스킬 — 규칙은 읽고, 아직 옮기지 않음

두 개를 켭니다.

- 스킬 `curator` (`skills/curator/SKILL.md`의 전시실 규칙)
- 도구 `propose_plan`

```yaml
tools: [list_files, peek_file, file_info, propose_plan]
skills: [curator]
```

"폴더를 정리해 줘"라고 하면 계획만 만듭니다. 파일은 아직 그 자리에 있습니다. 루프에 "스킬을 읽음"이 한 줄 나옵니다.

### 4. 승인 — 옮기기 전에 사람이 고름

- 도구 `move_files`를 켭니다
- 그 줄 오른쪽 **✋**도 켭니다

```yaml
tools: [list_files, peek_file, file_info, propose_plan, move_files]
ask_before: [move_files]
```

계획을 실행하려 하면 대화 칸에 승인 카드가 나옵니다. 항목마다 ✅ 두기, ❌ 빼기, ✏️ 위치 고치기. 승인하면 사본 안에서만 옮깁니다. 거절하면 그대로입니다. 덮어쓰지 않고, 지우지 않습니다. **↩️ 되돌리기**는 이렇게 옮긴 것만 원래 자리로 돌립니다.

### 5. MCP와 노트 — 웹에서 찾고, 파일을 쓰기 전에 보여 주기

1. 🧩의 **MCP**에서 Tavily를 켭니다. `mcp.json`의 `"enabled"`가 `true`가 되고, `web_search`와 `web_read`가 도구 목록에 나타납니다. 키는 `.env`의 `TAVILY_API_KEY`에서 읽습니다.
2. 도구 `write_file`을 켜고, 옆 **✋**도 켭니다. 승인 카드에 쓰려는 글이 먼저 보입니다.
3. 스킬 `research-note`를 켭니다. 노트는 한 줄 요약, 핵심, 출처 표, 더 물어볼 질문 순서입니다.

```yaml
tools: [..., web_search, web_read, write_file]
skills: [curator, research-note]
ask_before: [move_files, write_file]
```

웹에서 본 주소만 출처에 넣게 되어 있습니다. 노트는 사본 폴더 안의 `.md` 파일로만 새로 만들어지고, 이미 있는 파일은 덮어쓰지 않습니다. 되돌리기는 이 노트를 지우지 않습니다.

### 6. API와 팀 — 정리한 뒤 도슨트가 갤러리를 만듦

미술관 검색은 MCP가 아닙니다. `tools/met.py`가 메트로폴리탄 미술관 공개 API를 직접 부릅니다. 키는 필요 없습니다. 작품 제목, 작가, 연도, 이미지는 그 응답으로 채우고, 모델이 지어내지 않습니다. 갤러리의 출처는 이번 실행에서 웹 도구가 실제로 받은 주소만 남깁니다.

도슨트(`agents/docent/agent.yaml`)에는 이미 이 도구가 들어 있습니다.

```yaml
tools: [list_files, met_search, web_search, web_read, write_gallery]
```

화면의 **👥 팀 실행**을 누릅니다. 코드가 순서를 정합니다.

1. 나의 에이전트가 폴더를 정리합니다 (켜 둔 도구와 스킬만큼만).
2. 루프에 **넘겨주기**가 나오고, 앞 에이전트의 말이 보입니다.
3. 도슨트가 갤러리를 만듭니다. 각 에이전트의 루프는 칸으로 나뉩니다.

끝난 뒤 **🖼️ 갤러리**로 페이지를 엽니다. 순서가 마음에 안 들면 **↩️ 되돌리기**로 옮긴 파일을 돌립니다.

## 새 도구를 더하는 법

1. `tools/`에 파일을 만들거나, 있는 파일에 함수를 추가합니다.
2. 함수 바로 아래 설명(독스트링)은 **영어**로 적습니다. 그 글을 모델이 읽고 도구를 고릅니다. 학생에게 보이는 오류 문장은 한국어로 적어도 됩니다.
3. 함수 위에 `@tool("🔧", group="기타")`를 붙입니다. `needs="TAVILY_API_KEY"`처럼 적으면, 그 키가 없을 때 도구가 이유와 함께 꺼집니다.
4. `agents/my-agent/agent.yaml`의 `tools:`에 함수 이름을 넣습니다. 화면 체크박스와 같습니다.

파일을 지우는 도구는 만들지 않습니다. 도구가 실패하면 예외를 던지기보다 `error: 이유` 글을 돌려주세요.

예시 (`tools/weather.py`):

```python
from tools import tool

@tool("🌦️", group="기타")
def get_weather(city: str) -> str:
    """Get today's weather for a city."""
    return "맑음, 21도"
```

## 말 뜻

| 말 | 뜻 |
|---|---|
| 에이전트 | 목표를 받으면 할 일을 고르고, 도구로 해 보고, 결과를 보고 다음을 정하는 AI |
| 도구 | 에이전트가 부르는 함수. 이 키트에서는 `tools/` |
| 스킬 | 필요할 때 읽어 오는 일 매뉴얼. `skills/<이름>/SKILL.md` |

| API | 프로그램끼리 정보를 주고받는 창구. 여기서는 미술관 공개 API (`tools/met.py`) |
| 루프 | 고르기 → 해 보기 → 결과 보기 → 다시 고르기 |
| 승인 | 실행 전에 사람이 고르는 자리. `ask_before` |

## 이번 개편에서 하려던 것

한 저장소 안에 챗봇, 탐정, 큐레이터, 도슨트가 나뉘어 있고, 화면 위의 L1~L4 스위치로 에이전트를 바꿔 타고 있었습니다. 수업에서는 그게 "단계를 올린다"기보다 "다른 에이전트를 고른다"로 보였습니다. 도구 폴더 이름이 `hands`(손)라서, 도구 · 스킬 · MCP · API가 한 세트로 기억되지 않았습니다. 웹 검색 주소는 도구 코드 안에 숨어 있었습니다.

그래서 이렇게 바꾸려 했습니다.

- 학생이 키우는 에이전트는 `my-agent` 하나. 단계마다 `agent.yaml`에 줄이 늘고, 🧩에서 그 줄을 켭니다.
- `hands/`와 `hands:`와 `@hand`는 `tools/`, `tools:`, `@tool`로 바꿉니다.
- 웹 검색의 주소와 켜기는 `mcp.json`으로 빼서, 켜면 `web_search` / `web_read`가 보이게 합니다.
- 노트를 쓰는 `write_file`은 승인 카드에 내용을 먼저 보여 줍니다.
- 예전 L4 자리에는 **팀 실행**을 둡니다. 순서는 코드가 정하고, 누가 일하는지와 무엇을 넘기는지가 루프 칸에 보이게 합니다.
- 미술관 API, 번호로 파일 옮기기, 본 주소만 출처로 남기기, 되돌리기는 그대로 둡니다.

실제 키로 끝까지 돌려 보지는 못했습니다. 그래서 아래는 아직 확인이 부족합니다.

- Z.ai가 각 단계의 한국어 지시대로 도구를 고르는지 (특히 3단계에서 옮기지 않고 계획만 내는지)
- Tavily MCP 연결, 그리고 `.env`에 주소 전체를 넣었을 때의 접속
- 팀 실행에서 도슨트가 갤러리 HTML까지 만드는 모습. 이벤트 순서는 가짜 모델로 확인했습니다
- 브라우저에서 승인 카드의 고치기(✏️)를 눌러 보는 과정. 옮기기·되돌리기 자체는 시험으로 확인했습니다
- `docs/01`~`06`은 아직 L1~L4와 "손"이라는 말을 곳곳에 두고 있습니다. 고치지 않았습니다
- MCP는 Tavily 한 곳입니다. `mcp.json`에 다른 서버를 적어도, `tools/`에 그 도구 함수를 쓰기 전에는 생기지 않습니다. 검색 결과를 짧게 자르고 본 주소를 기록하는 코드는 `tools/web.py`에 남아 있습니다
- 되돌리기는 옮긴 파일만 돌아갑니다. `write_file`로 만든 노트는 지우지 않습니다
- 예전에 있던 L2(코드가 도구 순서를 대신 부르던 단계)는 뺐습니다. `count_by_type` 도구는 부품에 남아 있어서, 켜면 쓸 수 있습니다
